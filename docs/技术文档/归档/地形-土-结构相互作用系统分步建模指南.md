## 第一步：二维固定基础框架（建模与后处理链路验证）

本步骤脱离土体与土-结构相互作用（SSI），在隔离环境里验证“框架建模 + 抗震指标提取”两部分的正确性，为后续叠加 SSI、混凝土损伤塑性（CDP）以及距坡缘扫描奠定基础。

### 1. 核心文件
- **`frame_fixedbase_v1.py`**：负责建模与提交。实现了 2D 梁单元框架、楼层集中质量、模态步与隐式动力步的建立，并施加基底水平加速度输入。
- **`postproc_frame_v1.py`**：负责 ODB 后处理。用于提取模态一阶周期 \(T_1\)、基底剪力、层间位移角、楼层加速度，并进行手算锚点校核。

### 2. 运行方式
在工作目录下放置一条加速度记录 `.txt`（文件包含两列：时间 s，加速度 m/s²），然后运行：
```bash
abaqus cae noGUI=Modeling/Hybrid/frame_fixedbase_v1.py       # 建模 + 提交作业
abaqus cae noGUI=Postprocess/Hybrid/postproc_frame_v1.py     # 后处理 + 验证
```
可通过修改 `frame_fixedbase_v1.py` 顶部的配置字典，或在工作目录放置 `case_config.json` 文件来覆盖参数配置：
```json
{
  "frame_cfg":   {"n_story": 8, "n_bay": 3, "story_height": 3.2, "floor_mass": 6.0e4},
  "damping_cfg": {"ratio": 0.05, "f1": 0.8, "f2": 4.0}
}
```

### 3. 验证锚点
1. **模态周期 \(T_1\)**：应与经验公式（\(0.1 \cdot N\) 或 ATC 公式的 \(0.075 \cdot H^{0.75}\)）处于同一量级（在 0.5 ~ 2 倍范围内合理），用以验证刚度与质量。
2. **基底剪力校核**：\(\sum RF_1\) 与 \(\sum m_i \cdot a_i\)（绝对楼层加速度）的峰值比应在 \(1 \pm 0.1\) 之间，相关系数需大于 0.98，用以验证质量和反力的提取。
   *(小偏差通常来自质量比例阻尼 \(\alpha M v\)；若需要近乎严格的无阻尼对拍，可设 `damping_cfg.ratio=0` 单独运行验证)*。
3. **层间位移角**：计算相邻层水平位移差除以层高，其剖面形状应符合实际规律（一般中下层偏大），用以验证提取逻辑是否已自动扣除基底刚体运动。

后处理运行后会在相应目录下产生 `postproc_results.json`、`base_shear_check.csv` 和 `drift_profile.csv` 等结果文件。

### 4. 实跑验证结果
使用 5层3跨 框架、Ricker 子波（4Hz）作为输入，在 Windows 11 + Abaqus 2021 环境下实跑结果如下：

| 验证项 | 实跑结果 | 判据标准 | 状态 |
|:---|:---|:---|:---|
| 一阶周期 \(T_1\)（动力 FFT 反推） | 0.500s (比值 T1/0.1N=1.00) | 0.5 ~ 2 倍 | ✅ |
| 基底剪力 \(\sum RF_1\) vs \(\sum m_i a_i\) | 峰值比 1.001，相关系数 1.0000 | 比值 ≈ 1±0.1，相关 >0.98 | ✅ |
| 层间位移角 | 剖面形状合理（中部最大） | 符合结构层间位移物理规律 | ✅ |
| 楼层加速度 | 顶层加速度放大 1.83× | 沿高度单调合理放大 | ✅ |

### 5. 关键经验与踩坑记录
- **纯集中质量导致的特征值病态**：由于纯集中质量模型中旋转自由度（DOF）无质量，SIM-Lanczos 求解特征值时极易报 `rigid body modes / EXCEEDS expected` 并导致分析中止。
  - *解决方法*：给梁构件赋予微小的正则化密度 `density=10`（仅占楼层集中质量的 0.12%，对动力响应无物理影响），以消除奇异性。
- **高阶梁单元的内部节点缺失问题**：使用 B22 二次梁或 B23 三次梁时，会生成无质量的内部节点，且在 `BEFORE_ANALYSIS` 步极易触发 `general-section` 材料缺失的致命错误。
  - *解决方法*：改用 B21 线性梁单元，并保持每个物理构件划分 1 个单元的规则。
- **微扰步特征值奇异**：在使用 `DURING_ANALYSIS` 梁和 SIM Lanczos 时，微扰步解出的特征值可能会极小（接近 0），但不影响动力步刚度。
  - *解决方法*：一阶周期 \(T_1\) 改由动力响应顶层相对位移的 FFT 频谱反推获取（系统识别方法）。
- **Python 2.7 兼容性踩坑**：
  - 在后处理输出中文时，需要在脚本顶部添加 `reload(sys); sys.setdefaultencoding('utf-8')`。
  - 在解析 JSON 数据时，`json.load` 返回的 unicode 字符串直接作为 odb 关键字会报错，需显式使用 `str()` 进行类型转换。

### 6. 当前阶段边界
- **材料弹性**：为方便与解析/手算值对拍，第一步采用弹性材料（C30混凝土，\(E = 30\text{ GPa}\)）。在 `BeamSection` 中已使用 `integration=DURING_ANALYSIS` 为第三步（CDP/纤维截面非线性）预留了接口。
- **集中质量限制**：结构自重由楼层 `floor_mass` 集中质量主导，梁构件密度设为微小的 10 kg/m³。若后续需要考虑真实的构件自重，须调大密度并调小集中质量，同时重新校核 \(\sum m \cdot a\)。
- **构件单元划分限制**：每个梁/柱构件必须仅划分 1 个 B21 单元，不可细分，否则会在细分节点处产生无质量节点从而导致病态。

## 第二步（a）：二维框架-土相互作用（SSI）耦合机制验证

本步骤在第一步的基础上，引入土体，重点验证“土-结构相互作用（SSI）耦合机制”的正确性，包括：框架-土顶的 Tie 绑定、地震波通过土体底部的输入方式、侧边的周期边界条件（Equation 实现）以及 SSI 效应与固定基础的对比。
*为了隔离验证 SSI 效应，本阶段采用平层均质土与基底水平加速度输入，坡面几何与斜入射边界条件留待下一步处理。*

### 1. 核心文件
- **`frame_ssi_v1.py`**：同时建立并运行三个模型：`freefield`（纯土场地）、`ssi`（框架 Tie 绑定到土体表面）以及 `fixed`（去耦刚性基础对照组）。
- **`postproc_ssi_v1.py`**：读取三个 ODB 结果，提取并对比场地基频、SSI 下 of 结构周期延长、层间位移及刚性 vs SSI 的响应。

### 2. 运行方式
```bash
# 工作目录放一条加速度 .txt
abaqus cae noGUI=Modeling/Hybrid/frame_ssi_v1.py            # 建模 + 提交三个作业
abaqus cae noGUI=Postprocess/Hybrid/postproc_ssi_v1.py      # 后处理与去耦对比
```

### 3. 边界与耦合方案
- **基底边界**：使用刚性基底，通过 `AccelerationBC` 输入水平加速度时程，并限制竖向位移 \(U_2 = 0\)。
- **左右侧边**：施加周期 Equation 条件（使左右同高度节点水平与竖向自由度 \(U_1\) 和 \(U_2\) 强行相等），模拟土体纯一维剪切柱的变形机制。
- **土-结构耦合**：框架柱脚通过 Tie 绑定到土体表面，并将转动绑定关闭（`tieRotations=OFF`，即柱脚铰接）。结构的整体摇摆由多柱脚之间的竖向差动拉压变形来捕捉。
  - *注：平层 SSI 采用周期边界加刚性基底已足够，在此阶段不使用粘弹性边界（粘弹性边界是坡面散射才需要的，留待第二步(b)再叠加）。*

### 4. 实跑验证结果
（输入：Ricker 4Hz，5层3跨框架，土体 \(V_s = 300\text{ m/s}\)，深度 \(H = 30\text{ m}\)）

| 验证项 | 实跑结果 | 判据标准 | 状态 |
|:---|:---|:---|:---|
| 场地一维响应 | 地表放大 1.83×，主频 **2.50Hz** | \(\text{精确等于 } V_s / 4H = 2.50\text{ Hz}\) | ✅ |
| SSI 周期延长 | 结构自振周期由 0.500s 延长至 **0.667s** (1.33×) | \(T_{ssi} > T_{fixed}\) | ✅ |
| SSI 结构响应 | 基底剪力 \(2.02 \times 10^5\text{ N}\)，层间位移角 0.0020，顶层放大 1.68× | 处于合理响应区间 | ✅ |

*物理自洽性分析*：相比于固定基础，由于引入了基础土体的变形柔度，系统刚度变软，自振周期延长，层间位移增大，而基底剪力和顶层加速度均有所下降。这完全符合土-结构相互作用的一般物理规律。

### 5. 刚性基础与 SSI 的去耦对比（fixed 场景）
去耦对比是分析 SSI 效应的关键。其做法是：
1. 首先计算 `freefield` 模型（纯土），自动提取地表中心点（框架原柱脚对应位置）的自由场加速度时程。
2. 将此地表自由场时程作为输入，施加在无土体的单体 `fixed` 框架的基底。
3. 比较 `fixed` 与 `ssi` 两个模型的响应。两者唯一的输入和环境差异即为 SSI 效应。

| 性能指标 | 刚性基础 (fixed) | 考虑 SSI | SSI / 刚性比值 |
|:---|:---|:---|:---|
| 自振周期 \(T\) | 0.500s | 0.667s | 1.33 |
| 基底剪力 | \(1.27 \times 10^6\text{ N}\) | \(2.02 \times 10^5\text{ N}\) | 0.16 |
| 最大层间位移角 | 0.0037 | 0.0020 | 0.54 |
| 顶层加速度 | 9.47 (放大 9.5×) | 1.68 (放大 1.7×) | 0.18 |

- *物理机制解释*：在本算例中，刚性框架的自振主频为 2.0Hz，非常接近场地的一维基频（2.5Hz），从而发生了强烈的近共振响应，导致刚性基础下的加速度和剪力极大。而当考虑 SSI 效应后，由于结构周期延长（频率由 2.0Hz 降至 1.5Hz），结构成功**失谐并避开了场地的一阶共振带**，使得剪力和顶层加速度响应骤降。这证明了 SSI 效应对该体系起到了有利的减震作用。
- *踩坑记录*：在 Abaqus 2021 中，创建 Tie 绑定关系时必须使用旧版的 python 关键字 `master` 和 `slave`，新版的 `main` 与 `secondary` 会导致报错。

## 第二步（b）：框架坐坡顶与复用 Multi 引擎的坡面 SSI 集成

本步骤将土体由平层替换为真实的坡面地形。通过在代码中直接 import 复用已有的 Multi 引擎模块（`Modeling/Multi/VAB_oblique_multilayer_nonlinear_v3.py`），实现多层边坡场地、粘弹性人工边界（VAB）、以及斜入射 SV 波等效节点力等核心物理机制的耦合，并将结构框架坐于坡顶平台（紧邻坡肩）进行一体化模拟。

### 1. 核心文件
- **`frame_ssi_slope_v1.py`**：主脚本。复用 Multi 的场地引擎建立坡面场地及边界条件，生成框架并 Tie 绑定到坡顶土表，最终自动创建并提交 `freefield` 和 `ssi` 两个模型。
- **`postproc_ssi_slope_v1.py`**：ODB 后处理。用于提取坡顶自由场响应、结构自振周期、基底剪力及层间位移等指标。

### 2. 运行方式
```bash
# 工作目录放一条加速度 .txt
abaqus cae noGUI=Modeling/Hybrid/frame_ssi_slope_v1.py          # 建模并提交作业（小规模配置约 5-10 分钟）
abaqus python Postprocess/Hybrid/postproc_ssi_slope_v1.py       # 运行后处理
```

### 3. 多模块集成架构
为了规避重写复杂波动边界带来的物理风险，脚本采用模块导入方式进行集成：
```python
import VAB_oblique_multilayer_nonlinear_v3 as multi   # 通过多路径兜底导入（解决内核中 __file__ 缺失的问题）
multi.build_site / make_geometry / _resolve_damping   # 重用网格、几何与等效阻尼解析
multi.create_model(...)         # 建立坡面土体 Model-1（自动包含左右/底部的粘弹性人工边界）
mdb.models.changeKey(...)       # 将 Model-1 重命名为特定的场景名称
add_frame_on_crest(...)         # 将框架结构放置于坡顶（x=left_flat 处，右侧框架柱贴紧坡肩）并 Tie 绑定柱脚
ImplicitDynamicsStep + multi.VAB_oblique(...)   # 建立动力隐式分析步并施加斜入射等效动力荷载
```

### 4. 实跑验证结果
（输入：Ricker 4Hz，入射角 15° 斜入射，缩小尺寸坡：坡高 \(H_{upper} = 100\text{ m}\)，总长度 300m，网格尺寸 5m）

| 验证指标 | 计算值 | 物理意义与结论 |
|:---|:---|:---|
| **坡顶自由场放大** | **3.89×** (主频 3.0Hz) | 揭示了坡顶处的地形 + 土层双重叠加放大机理。 |
| **SSI 周期延长** | **0.667s** (自振周期从 0.500s 延长至 1.33×) | 与平层 SSI 延长效应完全一致，验证了坡顶 SSI 刚度退化的物理准确性。 |
| **坡顶结构响应** | 基底剪力 \(4.4 \times 10^5\text{ N}\)，漂移 0.0033，顶层放大 **4.67×** | 结构在已被地形放大的输入运动下发生二次放大，震害加重。 |

- *课题物理闭环*：斜入射 SV 波 \(\rightarrow\) 坡顶地形放大至 3.89× \(\rightarrow\) 坡顶建筑顶层最终放大至 4.67×。与平层场地相比（平层地表仅 1.83×，结构顶层仅 1.68×），坡顶处的建筑响应增大了近 3 倍。这以端到端定量模拟的方式证实了开题报告中“地形放大导致坡顶建筑震害加重”的核心物理机理。

### 5. 关键经验与踩坑记录
- **Assembly 节点的 NodeLabels 选择报错**：在 Abaqus 的 Assembly 层级上，直接使用 `SetFromNodeLabels(instanceName=...)` 会报关键字错误。
  - *解决方法*：改用 Assembly 的 Set 接口：`asm.Set(nodes=inst.nodes.sequenceFromLabels([lab]))`
- **内核无 `__file__` 属性导致相对路径失效**：在 Abaqus 内置 python 内核执行脚本时，系统不提供 `__file__` 属性，导致通过相对路径寻找 `Modeling/Multi` 模块失败。
  - *解决方法*：在集成脚本中，构建包含绝对路径以及多个潜在备用路径的兜底定位算法（多路径 list 插入到 `sys.path` 中）。
- **默认 Model-1 名称冲突**：由于 Multi 场地引擎内部写死了创建 `'Model-1'` 的逻辑，在建多个模型（如 ssi 和 freefield）时会出现名称覆盖。
  - *解决方法*：在 Multi 引擎建完后，利用 `mdb.models.changeKey(fromName='Model-1', toName=...)` 将其及时重命名为各步骤所需的特有场景名称。

### 6. 当前阶段边界
- **缩小尺寸网格**：本阶段为确保几分钟内快速跑完，采用了缩小的坡面模型配置（\(H_{upper}=100\text{ m}\)，网格 5m）。在后续论文成图时，仅需在 `soil_geometry_cfg` 中恢复真实的边坡尺度即可。
- **结构弹性与柱脚简化**：梁柱均为弹性构件，且柱脚与土体通过铰接 Tie 连接，未考虑底板等基础底座。

## 后续研发路线（下一步计划）
1. **进行 step2b-2（坡顶去耦对照）**：在坡面模型中增加 `fixed` 模型。提取 `freefield` 的坡顶节点 `CREST_REF` 的水平和竖向自由场加速度时程，并将其施加于固定基础框架的基底，对比分析坡顶环境下的 SSI 去耦效应。
2. **进行 step3（结构非线性）**：换用纤维截面或混凝土损伤塑性（CDP）模型，提取结构损伤指标，注意解决高度非线性下的隐式分析收敛性问题，必要时转为 Explicit 显式算法。
3. **进行 step4（距坡缘扫描）**：参数化 `x_off` 并配合 `case_config.json` 自动提交多工况任务，量化坡顶建筑相对于坡肩的距离对破坏模式的影响。
