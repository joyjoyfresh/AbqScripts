# 小论文研究流程手把手操作教程

_更新日期：2026-08-01_

本文把英文期刊小论文从有限元计算、数据提取、幅值—相位联合分析、代理模型训练，到真实地震波重构的完整流程，写成可以逐步照做的操作教程。

研究目标是：

> 研究地形与土层参数对复频响幅值—相位联合特征的影响规律，建立完整复频响代理模型，并通过真实地震波重构验证其工程有效性。

本文只讲小论文阶段的 V、H、P、B、C 五个批次，不包含毕业论文后续扩展工况。本文中的“程序已经具备”只表示脚本可以执行，不代表真实工况结果已经得到。

## 1. 先看懂整套研究流程

### 1.1 五类工况分别做什么

| 批次 | 工况 | 数量 | 研究用途 | 是否进入代理训练 |
|---|---|---:|---|---|
| V | P061基准、V001—V003 | 4 | 检查网格、计算域和信号处理变化带来的数值差异 | 否 |
| H | H001—H004 | 4 | 建立不同坡角下的均质基岩坡基线 | 否 |
| P | P001—P064 | 64 | 研究坡角、覆盖层厚度比和波速比的共同影响 | 是 |
| B | B001—B012 | 12 | 检查代理模型对未参与训练的中间参数组合的预测能力 | 否 |
| C | C001—C010 | 10 | 用真实地震波直接有限元结果检验代理重构效果 | 否 |

H、P、B、C 共 90 个小论文科学工况。V 批次另外提交 4 次，其中的 P061 是数值对照基准；P 批次中的 P061 仍按开发工况登记。

### 1.2 为什么幅值和相位必须一起研究

每个工况的核心输出是完整复频响：

$$
G_h(f,s)=\frac{A_{\mathrm{2D}}(f,s)}{A_{\mathrm{1D}}(f,s)}
$$

其中，$f$ 是频率，$s$ 是沿地表的归一化空间坐标。复频响同时包含：

- 幅值 $|G_h|$：表示不同频率和位置的放大或衰减；
- 相位 $\arg G_h$：表示波形在不同频率和位置上的超前、滞后与旋转；
- 群时延：由相位随频率的变化得到，用来描述波包到达时间的变化；
- 空间相位梯度：由相位随地表位置的变化得到，用来描述传播特征；
- 幅值—群时延相关性：用于观察强放大位置是否同时伴随明显时延变化。

代理模型不是只预测一条幅值曲线，而是联合预测 $G_h$ 的实部和虚部。这样才能在真实波重构时同时保留幅值和相位信息。

### 1.3 正确执行顺序

建议严格按下面顺序操作：

~~~text
V数值对照
  ↓
H均质基线
  ↓
P开发矩阵
  ↓
H+P联合分析和P池五折模型比较
  ↓
B未见组合检验
  ↓
H+P+B最终联合分析和最终代理模型
  ↓
C真实波直接有限元
  ↓
代理复频响驱动的真实波重构与直接有限元对比
  ↓
整理图表并撰写小论文
~~~

H 和 P 在技术上可以同时运行，但两个批处理入口都默认最多并行 4 个 Abaqus 工况，同时启动可能变成 8 个求解任务。为避免内存和磁盘争用，本文按 H 完成后再运行 P 的顺序讲解。

## 3. 认识批处理、后处理和独立分析的分工

每个批处理入口只负责三件事：

1. 为每个工况创建目录并写入 case_config.json；
2. 调用 Abaqus 建模和求解；
3. 调用 Postprocess_All_surface_v2.py，从 ODB 提取并保存规范数据。

Postprocess_All_surface_v2.py 只做数据读取、计算和保存。它不比较模型好坏，也不决定研究结论。

其余工作全部由独立脚本完成：

| 工作 | 独立脚本 |
|---|---|
| V批次数值差异检查 | Postprocess/General/evaluate_complex_frf_quality.py |
| 幅值—相位联合分析 | Postprocess/General/analyze_complex_frf.py |
| 复频响代理训练 | ML/train_complex_frf_surrogate.py |
| 真实波重构与直接有限元对比 | ML/reconstruct_real_wave.py |

这样即使以后改变评价指标，也不需要重新读取 ODB，更不会把“数据提取成功”和“研究结果理想”混成一件事。

## 4. 学会判断一个工况是否完成

### 4.1 看批次总清单

每个批次根目录都有 run_manifest.json。以 V 批次为例：

~~~powershell
$Manifest = Get-Content -LiteralPath "$Repo\Run\ch4_sp_01_V\run_manifest.json" -Encoding UTF8 -Raw | ConvertFrom-Json
$Manifest.cases.PSObject.Properties.Value | Select-Object case_id, status | Format-Table -AutoSize
~~~

常见状态含义：

| 状态 | 含义 |
|---|---|
| planned | 已登记，尚未开始 |
| model_running | 正在建模或求解 |
| model_completed | 有限元已完成，尚未完成数据提取 |
| postprocess_running | 正在从 ODB 提取数据 |
| data_ready | 规范数据已生成 |
| model_failed | 建模或求解失败 |
| postprocess_failed | 有限元可能已完成，但数据提取失败 |

只有 data_ready 表示该工况已走完当前批处理流程。

### 4.2 看每个工况的三个核心结果

一个可供后续研究使用的工况应至少有：

- surface_results.npz：供联合分析和机器学习读取；
- surface_results.xlsx：供人工查看和论文整理；
- freefield_reference_*.npz：与该工况同地层、同输入的精确一维参考。

检查某个批次的文件数量：

~~~powershell
$Root = "$Repo\Run\ch4_sp_01_V"
[PSCustomObject]@{
    Cases = (Get-ChildItem -LiteralPath $Root -Directory -Filter "case-*").Count
    NPZ = (Get-ChildItem -LiteralPath $Root -File -Recurse -Filter "surface_results.npz").Count
    XLSX = (Get-ChildItem -LiteralPath $Root -File -Recurse -Filter "surface_results.xlsx").Count
    References = (Get-ChildItem -LiteralPath $Root -File -Recurse -Filter "freefield_reference_*.npz").Count
}
~~~

四个数量应与该批次的工况数一致。

### 4.3 看后处理执行状态

执行：

~~~powershell
Get-ChildItem -LiteralPath $Root -File -Recurse -Filter "postprocess_status.json" | ForEach-Object {
    $Status = Get-Content -LiteralPath $_.FullName -Encoding UTF8 -Raw | ConvertFrom-Json
    [PSCustomObject]@{
        Case = $_.Directory.Name
        Success = $Status.success
        Status = $Status.status
    }
} | Format-Table -AutoSize
~~~

每个工况应显示 Success=True、Status=completed。这只表示数据写出成功，不表示该工况的物理结果一定符合预期。

1. peak_amplitude、peak_frequency_hz、peak_s：最强放大发生多大、在哪个频率、哪个位置；
2. phase_at_peak_deg：最强放大点的相位；
3. group_delay_at_peak_s：最强放大点的时延；
4. phase_rotation_near_peak_deg：峰值附近的相位旋转；
5. median_abs_spatial_phase_gradient_rad_per_s：相位沿地表变化的整体强度；
6. amplitude_group_delay_correlation：幅值增强与时延变化是否同步。

再打开 layer_correction_metrics.csv。这里的复数修正同时回答“土层把幅值改了多少”和“土层把相位改了多少”，不能只摘取幅值列。

最后查看 parameter_effects.csv 和 figures，分别比较坡角、厚度比、波速比变化时：

- 峰值幅值和峰值频率如何移动；
- 相位旋转和群时延如何变化；
- 坡前、坡面、坡后三个区域是否表现不同；
- 幅值增强是否伴随更大的时延或空间相位梯度。

## 12. 第八步：用代理复频响重构真实波

### 12.1 重构原理

对每个 C 工况，程序先用地形和土层参数预测完整复频响，再与该工况的精确一维参考频谱相乘：

$$
A_{\mathrm{2D,pred}}(f,s)=G_{h,\mathrm{surrogate}}(f,s)A_{\mathrm{1D}}(f,s)
$$

最后通过逆变换得到预测时程。因为 $G_h$ 是复数，所以幅值放大和相位移动都会进入重构结果。

### 12.2 批量重构全部 C 工况

执行：

~~~powershell
Set-Location -LiteralPath $Repo
python "$Repo\ML\reconstruct_real_wave.py" --model "$Repo\Run\ch4_sp_model\complex_frf_surrogate.pkl" --truth-root "$Repo\Run\ch4_sp_05_C" --output "$Repo\Run\ch4_sp_reconstruction"
~~~

脚本会扫描 C 根目录下具有 surface_results.npz 的 case-* 目录，读取每个工况的参数、真实波记录、精确一维参考和直接有限元结果。

每个重构工况目录中应生成：

- reconstruction.npz：完整重构数据；
- reconstruction_by_s.csv：各地表位置的指标；
- reconstruction_metrics.json：重构设置和汇总；
- reconstruction_overview.png：重构时程、PGA 和 TAF 概览；
- direct_fe_comparison.png：代理重构与直接有限元时程对比。

### 12.3 怎样评价重构效果

打开 reconstruction_by_s.csv 和图片，依次检查：

1. time_nrmse：预测时程与直接有限元时程的归一化误差；
2. correlation：两条时程的相关系数；
3. pga_relative_error：峰值加速度相对误差；
4. peak_time_error_s：峰值出现时刻的误差；
5. taf_relative_error：地形放大系数相对误差；
6. response_spectrum_relative_error_median：5% 阻尼反应谱中位相对误差。

所有时程、PGA、TAF 和反应谱比较都在代理公共频带内进行。不要把全频直接有限元指标与带限重构指标混在一起。

### 12.4 单个工况调试方法

如果批量重构只有一个工况失败，可单独运行：


## 14. 常见失败及处理方法

### 14.1 启动时提示源文件缺失

重新执行第 2.3 节的文件检查。确认文件真实存在后再启动，不要通过删除配置项绕过。

### 14.2 工况显示 model_failed

操作顺序：

1. 查看工况目录下 autorun_step 开头的日志、建模日志、dat、msg 和 sta；
2. 确认没有该工况的 standard.exe 或 SMAPython.exe；
3. 根据日志修复明确问题；
4. 保留失败工况的 ODB 和日志，便于核对；
5. 只处理该工况，不要删除整个批次目录。

若配置和已有输入仍有效，可进入该工况目录，用仓库中的当前建模脚本单独执行：

~~~powershell
Set-Location -LiteralPath "需要处理的工况绝对路径"
& $Abaqus cae "noGUI=$Repo\Modeling\slope_frame_ssi_full_v2.py"
~~~

### 14.3 工况显示 postprocess_failed

先确认有限元是否成功：

~~~powershell
Get-ChildItem -LiteralPath "需要处理的工况绝对路径" -Filter "*.sta" | ForEach-Object { Get-Content -LiteralPath $_.FullName -Tail 30 }
Get-ChildItem -LiteralPath "需要处理的工况绝对路径" -Filter "*.odb"
~~~

如果求解成功且 ODB 存在：

1. 检查是否已有 freefield_reference_*.npz；
2. 若没有，按第 5.4 节的 ABQ_REFERENCE_ONLY 方法补生；
3. 在工况目录调用当前 Postprocess_All_surface_v2.py；
4. 检查 NPZ、XLSX 和 postprocess_status.json。

不要因为数据提取失败就立刻重做有限元。

### 14.4 联合分析提示缺少完整一维参考

这表示不能构造定义完整的 $G_h$。回到对应工况补生精确一维参考，然后重新运行该工况后处理。不要用入射波替代。

### 14.5 代理训练提示 P 工况不足

检查：

~~~powershell
Import-Csv "$Repo\Run\ch4_sp_analysis_dev\case_metrics.csv" | Group-Object group | Select-Object Name, Count
~~~

P 必须为 64。若少于 64，回到 P 批次查找缺失或失败工况，不要降低最低数量继续训练。

### 14.6 重构提示找不到参考或真实记录

依次检查：

- C 工况的 case_config.json；
- C 工况的 surface_results.npz；
- freefield_reference_*.npz；
- Wave/Seismic/Sp_EQ 中的真实波文件；
- sp_eq_input_manifest.json 中记录名和路径。

### 14.7 出现 lck 锁文件

先查 Abaqus 进程。只有确认对应工况没有 standard.exe、SMAPython.exe 或 Abaqus CAE 进程后，才处理该工况的旧锁文件。不要在求解仍运行时删除锁文件。

### 14.8 为什么成功工况可能没有 ODB

批处理只有在 NPZ、XLSX 和后处理状态都确认成功后，才清理体积较大的过程文件；CAE 文件保留。失败工况不会执行这一步，因此 ODB 和日志会留在目录中供排查。
